# Pult: архитектура и роадмап

Pult (раньше SSH Client): десктопный SSH-клиент уровня Termius на Electron с дополнениями: broadcast, вложенные папки, сетевая карта, устаревшие алгоритмы для Huawei, открытие хоста в браузере, WinBox, LDAP.

Дата: 2026-10-09. Статус: черновик v1, каркас лежит рядом в этой же папке.

---

## 1. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Оболочка | **Electron** (44.x) | решено владельцем |
| Сборка | **electron-vite** + Vite 7, TypeScript | быстрый HMR, отдельные бандлы main / preload / renderer |
| UI | **React 19** | экосистема, React Flow для карты |
| Терминал | **@xterm/xterm** + addon-fit, addon-search, addon-web-links | стандарт де-факто (VS Code, Hyper, Tabby) |
| SSH / SFTP | **ssh2** (mscdex, pure JS) | поддерживает и современные, и старые алгоритмы (ssh-rsa SHA-1, dh-group1/14-sha1, aes-cbc, 3des), SFTP, port forwarding, jump host через `sock` |
| Хранилище | **better-sqlite3** (этап 2), в каркасе JSON-файл | транзакции, вложенные папки и связи карты удобнее в SQL |
| Секреты | **Electron safeStorage** (DPAPI / Keychain / libsecret) + опциональный мастер-пароль (AES-256-GCM, ключ из scrypt) | пароли и ключи никогда не лежат открытым текстом |
| Сетевая карта | **@xyflow/react** (React Flow) | узлы, связи, drag-n-drop, мини-карта из коробки |
| LDAP | **ldapts** | промисный клиент, LDAPS / StartTLS |
| Упаковка | **electron-builder** | NSIS для Windows, AppImage / deb для Linux |

### Процессная модель

```
┌──────────── main (Node) ────────────┐        ┌──────── renderer (React) ────────┐
│ SessionManager  (ssh2 Client/Stream)│◄──IPC──►│ вкладки, xterm.js, дерево хостов │
│ Broadcast       (fan-out ввода)     │ preload │ сетевая карта (React Flow)       │
│ Store           (SQLite + safeStorage)        │ broadcast-панель                 │
│ Integrations    (browser, WinBox, LDAP)       └──────────────────────────────────┘
└─────────────────────────────────────┘
```

Renderer не имеет доступа к Node: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Всё общение идёт через узкий API в `preload` (`window.api.*`). Пароли и ключи не уходят в renderer: он передаёт только `hostId`, а main сам достаёт секрет.

## 2. Модель данных

```sql
folders     (id, parent_id NULL → folders.id, name, sort, color, defaults_json)
hosts       (id, folder_id → folders.id, name, address, port, protocol,
             identity_id NULL, jump_host_id NULL, algo_profile, web_url,
             winbox_enabled, tags, notes, overrides_json)
identities  (id, name, username, auth_type[password|key|ldap|agent],
             secret_ref, key_ref, passphrase_ref)
secrets     (id, ciphertext BLOB)           -- шифруется safeStorage
maps        (id, name, sort)                -- «листы» карты
map_nodes   (id, map_id, host_id NULL, label, kind[host|cloud|label|group], x, y, w, h, style_json)
map_links   (id, map_id, from_node, to_node, from_if, to_if, label, style_json)
snippets    (id, folder_id NULL, name, body)
known_hosts (address, port, key_type, fingerprint_sha256, added_at)
```

### Вложенные папки и наследование
- Дерево через `parent_id`, глубина не ограничена; выборка поддерева рекурсивным CTE (`WITH RECURSIVE`).
- У папки есть `defaults_json`: пользователь, порт, identity, jump host, профиль алгоритмов, шаблон веб-URL. Хост наследует всё, чего не задал сам. Итоговые настройки вычисляются проходом от корня к хосту: `effective = merge(root.defaults, …, folder.defaults, host.overrides)`.
- Пример: папка «Huawei / Филиал-1» с `algo_profile = legacy`, `username = admin` — все свитчи внутри сразу подключаются со старыми алгоритмами.
- Drag-n-drop хостов и папок между папками; групповые действия на папку: «подключиться ко всем», «broadcast на папку», «открыть все в браузере».

### Сетевая карта
- Несколько **листов** (`maps`), как вкладки в Excel: «Ядро», «Филиал-1», «DMZ».
- Узел может ссылаться на хост (`host_id`) или быть декоративным (облако провайдера, подпись, группа-рамка). Один хост может стоять на нескольких листах.
- **Связи** хранят интерфейсы с обеих сторон (`GE0/0/1 ↔ ether3`) и подпись (VLAN, скорость).
- Действия с узла: двойной клик открывает SSH, ПКМ даёт меню «Подключиться / Подключиться к выбранным / Браузер / WinBox / Убрать с листа», узел помечается, если сессия открыта.
- Выбор нескольких узлов (Ctrl + клик или Shift + рамка) и кнопка «Подключиться к N» открывают их в сетке одной broadcast-группой.
- Узлы и связи окрашены по мониторингу (раздел 11): зелёная связь, если оба конца живы, красный пунктир, если один недоступен. Связь цепляется к обращённым друг к другу сторонам узлов.
- Реализация: React Flow (`@xyflow/react`), `src/renderer/src/map/`. Позже: импорт соседей по LLDP (`display lldp neighbor` / `/ip neighbor print`).

## 3. Устаревшие алгоритмы для Huawei (ssh-rsa)

Старые прошивки Huawei VRP часто умеют только `ssh-rsa` (SHA-1), `diffie-hellman-group1/14-sha1`, `aes*-cbc`/`3des-cbc`, `hmac-sha1`. OpenSSH 8.8+ и многие клиенты это отключили, а **ssh2 поддерживает всё это, но не включает по умолчанию**. Мы включаем явно и только там, где нужно.

Профили (`src/main/ssh/algorithms.ts`):
- **modern** — дефолт ssh2 (curve25519, ed25519, rsa-sha2-256/512, aes-gcm, chacha20).
- **compat** — modern **плюс** в конец списков добавлены legacy-алгоритмы. Порядок важен: с новым сервером договоримся о современных, со старым откатимся на старые.
- **legacy** — старые алгоритмы в начале списка, для совсем капризных устройств.

```ts
algorithms: {
  serverHostKey: [...modern, 'ssh-rsa', 'ssh-dss'],
  kex: [...modern, 'diffie-hellman-group14-sha1', 'diffie-hellman-group-exchange-sha1', 'diffie-hellman-group1-sha1'],
  cipher: [...modern, 'aes128-cbc', 'aes192-cbc', 'aes256-cbc', '3des-cbc'],
  hmac: [...modern, 'hmac-sha1', 'hmac-md5'],
}
```

Тонкости:
- **Electron и BoringSSL (проверено).** В Electron вместо OpenSSL стоит BoringSSL, в нём нет групп modp1/modp2, и `diffie-hellman-group1-sha1` в чистом ssh2 падает с «Unknown DH group», хотя в обычном Node работает. В каркасе это исправлено шимом `src/main/ssh/dh-groups.ts`, который отдаёт простые числа RFC 2409 через `createDiffieHellman`. Проверено `npm run test:legacy` против эмулятора: сервер только с dh-group1-sha1 + ssh-rsa + aes128-cbc + hmac-sha1, профиль modern получает отказ, compat и legacy подключаются.
- **Ключ пользователя RSA.** ssh2 подписывает `rsa-sha2-*`, если сервер объявил `server-sig-algs`; старый VRP этого не делает, и тогда ssh2 откатывается на `ssh-rsa` (SHA-1). Это как раз нужное поведение, но его надо проверить на реальном железе.
- **Длина ключа.** Некоторые старые VRP не принимают RSA > 2048 бит. В генераторе ключей даём выбор 2048 / 3072 / 4096 и подсказку.
- **Форматы ключей.** OpenSSH, PEM (PKCS#1/#8), PuTTY .ppk. Импорт .ppk полезен для тех, кто переходит с PuTTY.
- **keyboard-interactive.** Многие Huawei/Cisco спрашивают пароль именно так; обработчик `keyboard-interactive` отвечает сохранённым паролем, а если промпт неизвестен, показывает диалог.
- **Понятные ошибки.** На `no matching key exchange / host key` показываем «Сервер поддерживает только устаревшие алгоритмы: [список]. Включить профиль compat для этого хоста?» с кнопкой. Список алгоритмов сервера берём из события `handshake` / отладочного лога ssh2.
- В UI у хоста и папки выпадающий список «Профиль алгоритмов» и бейдж ⚠ legacy во вкладке.

## 4. Broadcast (ввод в несколько сессий)

- **Группа broadcast** = набор открытых сессий. Собирается кнопкой broadcast в заголовке панели, «Выбрать все» или «Подключиться ко всем» на папке.
- **Сетка без ограничения** (сделано): все сессии на одном экране, `⌈√n⌉` колонок; любую панель можно развернуть или вынести в отдельное окно ОС. При закрытии окна сессия возвращается в главное. Новое окно получает вывод сессии из буфера main-процесса (512 КБ), живой вывод сверяется по смещению, чтобы не было дублей.
- Два режима:
  1. **Панель ввода**: отдельная строка снизу, Enter отправляет команду во все сессии группы.
  2. **Синхронный ввод**: каждое нажатие в активном терминале дублируется (как `synchronize-panes` в tmux). Нужен для интерактива: Tab, `?`, стрелки в CLI Huawei.
- Реализация в main: `SessionManager.write(sessionId, data)`; broadcast просто проходит по набору id. Renderer шлёт один IPC-вызов `broadcast(ids, data)`, а не N штук.
- Безопасность: яркая рамка и счётчик «→ 12 хостов» на всех участвующих вкладках; опционально подтверждение перед Enter для команд из стоп-листа (`reboot`, `reset saved-configuration`, `undo`, `/system reset-configuration`).
- Сетка терминалов (2×2, 3×3) для наблюдения за выводом с нескольких хостов сразу.

## 5. Открыть хост в браузере

- У хоста или папки задаётся шаблон `web_url`, по умолчанию `https://{address}`. Подстановки: `{address}`, `{port}`, `{name}`, `{username}`.
- Варианты открытия:
  - **системный браузер** через `shell.openExternal` (по умолчанию);
  - **встроенная вкладка** через `BrowserWindow` / `WebContentsView` с отдельной `session` на хост: можно разрешить самоподписанный сертификат только для этого хоста (`setCertificateVerifyProc`), не ослабляя проверку глобально.
- Пункт есть в контекстном меню хоста, на узле карты и по хоткею.

## 6. Интеграция с WinBox

- В настройках указывается путь к `winbox64.exe` (Windows) или команда запуска через Wine (Linux).
- Запуск: `child_process.spawn(winboxPath, [address, username, password], { detached: true })`. WinBox 3.x принимает `winbox.exe <адрес> <логин> <пароль>`.
- Пароль сохранённой учётки хоста (своей, папки или выбранной из «Учётки») передаётся по умолчанию, WinBox сразу входит. Риск: пароль виден в списке процессов (диспетчер задач, Process Explorer). В настройках «WinBox → Передавать пароль» можно выключить, тогда запуск только с адресом и логином. За мастер-кеем адрес заменяется на локальный туннель 127.0.0.1:порт.
- WinBox 4 (новый кроссплатформенный) поддерживает те же аргументы; проверим на реальной версии, которая у вас стоит.
- Флаг `winbox_enabled` у хоста или папки, чтобы пункт «WinBox» появлялся только у MikroTik.

## 7. Интеграция с LDAP

**Решено (Алексей, 2026-10-09).** Делаем после базового клиента.

- Сеть огромная, LDAP/AD уже настроен. Команда создаёт в AD группу (через GPO) со своими учётками, под которыми ходят на оборудование.
- В клиенте LDAP нужен, чтобы **подключить эту группу/OU из AD как папку учёток**: клиент читает список учёток (`ldapts`, bind текущей доменной учёткой), пользователь выбирает свою, пароль проверяется bind-ом и сохраняется зашифрованным. Дальше эта учётка назначается папке хостов так же, как сейчас общий пароль папки.
- **Синхронизации между пользователями нет.** База хостов локальная: у каждой учётной записи Windows своя (`%APPDATA%/ssh-client`; путь закреплён в `src/main/index.ts`, чтобы переименование в Pult его не сменило), вне LDAP. Она основная.
- Сервер синхронизации, командные хранилища и вход в само приложение по LDAP не делаем.

Настройки: URL (`ldaps://dc.corp.local:636`), base DN группы/OU, фильтр, CA-сертификат.

## 8. Базовые функции уровня Termius

- Вкладки и сплиты терминалов, поиск по выводу, копирование по выделению, настраиваемые шрифты и темы.
- Known hosts с подтверждением отпечатка (SHA-256) при первом подключении и тревогой при смене ключа: сделано, см. раздел 12.
- Jump host через `forwardOut` + `sock`: сделан для одного мастер-кея, см. раздел 14.
- Port forwarding: локальный, удалённый, динамический (SOCKS).
- SFTP-панель: двухпанельный менеджер, drag-n-drop, прогресс.
- Генерация и импорт ключей, SSH-агент (Pageant / OpenSSH agent).
- Автопереподключение, keepalive (`keepaliveInterval`), логирование сессии в файл.
- Поиск по хостам, теги, быстрый коннект `Ctrl+K`.
- Импорт из `~/.ssh/config`, PuTTY (реестр), Termius (CSV), экспорт и импорт бэкапа.
- Telnet как дополнительный протокол (для старого железа часто нужен) — кандидат на этап 3.

## 9. Безопасность

- Renderer изолирован, CSP без `unsafe-eval`, никаких удалённых страниц в основном окне.
- Секреты шифруются safeStorage; при включённом мастер-пароле дополнительно AES-GCM с ключом из scrypt, автоблокировка по таймеру.
- IPC валидирует аргументы (zod) и принимает только `hostId`, а не сырые креды.
- Legacy-алгоритмы включаются точечно на хост или папку, никогда не глобально.

## 11. Мониторинг без VTY-линий

- Main-процесс раз в N секунд (Настройки, по умолчанию 30) опрашивает хосты, у которых включены ping или SNMP. Параллельно до 24 хостов, история 30 последних замеров. SSH не используется, VTY-линии на устройстве не заняты.
- **Ping**: системная утилита (`ping -n 1 -w` на Windows). Вывод читается как latin1 и разбирается по `TTL=`, поэтому работает и на русской Windows (cp866), и на английской. Тест: `test/ping-parse.mjs`.
- **SNMP v2c** (UDP 161, `net-snmp`): sysName, sysDescr (строка с версией), sysUpTime, sysObjectID. Температура по вендору: Huawei `hwEntityTemperature`, MikroTik `mtxrHlTemperature` / gauge-таблица, Cisco `ciscoEnvMonTemperatureStatusValue`, иначе ENTITY-SENSOR (тип 8, °C). Берётся максимум по платам.
- Community хранится как секрет `snmp:<id папки или хоста>`, наследуется вниз, как пароль.
- Хост «жив», если ответил ping или SNMP. Состояние уходит в renderer событием `monitor:update`; открытие листа карты запускает внеочередной опрос его хостов. События идут пачками (не чаще раза в секунду), а не по одному на хост. На карте узел, у которого ничего не поменялось, остаётся тем же объектом (React Flow его не перерисовывает и не перемеряет), а сохранение стора показывается сразу, не дожидаясь ответа main: иначе статусы во время сохранения откидывали перетащенный узел назад (`test/e2e-jitter.cjs`).
- На устройствах нужен SNMP v2c read-only с доступом с IP рабочей станции. Huawei: `snmp-agent community read <community> acl <N>`, `snmp-agent sys-info version v2c`. MikroTik: `/snmp set enabled=yes`, community с `addresses=`.

## 12. Ключи хостов и учётки

- `ssh2.hostVerifier` асинхронный: main считает отпечаток `SHA256:…` и тип ключа, сверяет с `knownHosts["адрес:порт"]` в store.json. Совпал — подключаемся молча. Новый или изменился — запрос в renderer (`hostkey:ask`), подключение ждёт ответа. Отмена даёт ошибку «ключ хоста не подтверждён».
- Очередь запросов: при «Подключиться ко всем» можно подтвердить все новые ключи разом; изменённые всё равно спрашиваются по одному.
- **Учётные данные** — отдельная коллекция `credentials` (имя, логин), пароль в секретах под id учётки. Хост или папка ссылаются на неё `credentialId`; ближайший уровень (хост, затем папки вверх), где задана учётка или свой пароль, побеждает. Удаление учётки снимает ссылки.

- Electron 23 и новее не запускаются на Windows 7, 8, 8.1, Server 2012 и 2012 R2. Клиент работает на рабочих станциях Windows 10/11.
- Решение владельца (2026-10-10): мастер-кей с OpenSSH используется как jump-host, раздел 14.

## 14. Jump-host (мастер-кей или SOCKS5)

- Настройки → «Jump-host»: тип (SSH или SOCKS5), адрес, порт, сохранённая учётка, профиль алгоритмов (только SSH). Применяется ко всем хостам, и существующим, и новым. Папка или хост выключает его флагом `jump: false` (наследуется, как остальные поля).
- `src/main/ssh/jump.ts`: одно SSH-подключение к мастер-кею на весь клиент, как ControlMaster в OpenSSH. Каждая сессия до коммутатора — канал direct-tcpip (`forwardOut`) внутри него, ssh2 получает его как `sock`. 20+ сессий = один вход на мастер-кей. На сервере нужен `AllowTcpForwarding yes` (по умолчанию так).
- Ключ мастер-кея проверяется так же, как ключи коммутаторов (окно подтверждения, `knownHosts`).
- Веб-морда и WinBox: локальный TCP-туннель `127.0.0.1:<случайный порт>` → мастер-кей → `адрес:443/80/8291`. Браузер открывается на локальном адресе, WinBox получает `127.0.0.1:порт`.
- Ping и SNMP идут с рабочей станции напрямую (обычно ICMP и SNMP до коммутаторов открыты, а SSH ограничен ACL на VTY только с мастер-кея).
- Тип SOCKS5 (`JumpHost.kind = 'socks5'`, порт по умолчанию 1080): `src/main/ssh/socks5.ts`, свой клиент RFC 1928 + вход по логину и паролю RFC 1929, без зависимостей. Каждая SSH-сессия — отдельное TCP-подключение через прокси (CONNECT), сокет отдаётся ssh2 как `sock`. Имена хостов резолвит прокси. Логин и пароль берутся из сохранённой учётки (пароль в safeStorage, как все секреты); «Без авторизации» — прокси без входа. Веб-морда, WinBox и проверка портов в Инструментах идут через те же локальные туннели. SNMP (UDP) через SOCKS5 не проходит и идёт напрямую.
- Пинг мониторинга: переключатель «Напрямую (ICMP)» / «Через прокси (TCP)» (`JumpHost.pingVia`, для обоих типов jump-host). Через jump-host это `tcpPing` (`main/monitor/ping.ts`): время открытия TCP-подключения к SSH-порту хоста через `jump.forward`; отказ (SOCKS5 reply 5 или «Connection refused» от OpenSSH) тоже значит «жив»; таймаут 3 с или упавший прокси = нет ответа. `HostStatus.probe` подписывает такой пинг в подсказке списка хостов. Хосты с `jump: false` пингуются ICMP напрямую. Тест: `npm run test:socks5` (мок-прокси, ошибки, реальная ssh2-сессия через прокси).
- Очередь открытия сессий (`main/ssh/open-queue.ts`, `OpenQueue` в обработчике `ssh:connect`): не больше 3 сессий одновременно в handshake, для прямых и для jump-подключений. Мастер-кей (MaxStartups) и SOCKS5-прокси молча рвут лишние одновременные подключения, ssh2 пишет «Connection lost before handshake»; так открытие пачки с карты давало максимум 3 сессии. Обрыв до handshake (а также ECONNRESET, «прокси закрыл соединение» и текстовый ответ занятого коммутатора вместо строки версии SSH: «Invalid header: expected newline») освобождает слот, снижает параллельность на 1 (до 1) и повторяется через 1,5 и 3 с; после того как пачка открылась, параллельность снова 3. Неверный пароль, закрытый порт и отказ от ключа не повторяются. Тест: `npm run test:burst` (мок мастер-кея и SOCKS5 перед сервером, который рвёт подключения сверх лимита в handshake).

## 15. Порядок алгоритмов

- Профиль «Авто» отправляет серверу один список: сначала современные алгоритмы, в конце старые. Сервер выбирает первый общий за один обмен (RFC 4253, 7.1), перебора нет, поэтому порядок не замедляет подключение ни к новым, ни к старым устройствам.

## 16. Карта: вложенные листы и анимации

- `NetMap.parentId`: лист внутри листа. На родителе он стоит узлом `sheetId`, двойной клик открывает, сверху хлебные крошки. Узел показывает сводку по хостам всего вложенного дерева; связь к нему окрашивается по этой сводке. Удаление узла или листа удаляет вложенные листы после подтверждения.
- Связи (`edges.tsx`): форма `curve | straight | step` и точка изгиба `bend` относительно середины; тянется за маркер на выбранной связи, двойной клик выпрямляет.
- Анимации (Настройки, по умолчанию включены; выключаются системным «уменьшить движение»): по живым связям бежит трафик.
- Зоны (`NetMap.zones`, `MapZone`: shape `rect | square | circle`, имя, цвет, x/y/w/h). В React Flow зона это узел `zone` с `zIndex: -1000`, хосты в ней дочерние (`parentId`, позиция относительно зоны); в базе у узла `zoneId`, а x/y всегда абсолютные, поэтому старые версии и экспорт читают их как есть. Обёртка зоны с `pointer-events: none`: ловят мышь только название (dragHandle), рамка и ручки `NodeResizer`, внутри зоны лист двигается и выделяется рамкой как обычно. Принадлежность пересчитывается по центру узла: у перетащенных узлов при отпускании, у всех после изменения размера зоны; при пересечении берётся меньшая зона. Удаление зоны (Delete, меню) оставляет хосты на месте: `onBeforeDelete` не даёт React Flow удалить детей вместе с родителем.
- Позиции пишутся в базу через `pendingLayout`: drag stop и конец ресайза ставят флаг, эффект сохраняет уже на следующем рендере с финальными позициями. Перестройка узлов при обновлении статуса не трогает узел, который сейчас тянут или ресайзят.
- `Host.icon` (`HostIcon`): значок хоста, без него роутер для WinBox и сервер для остальных (`hostIcon` в util). Групповая смена значка и цвета: `sheets/AppearanceSheet.tsx`, `applyAppearance` чистая функция над Store.

## 17. Сборка

- `npm run dist:win` → `dist/Pult-Setup-<версия>.exe` (NSIS, установка в профиль пользователя) и `Pult-<версия>-portable.exe`. Иконка `build/icon.ico` (из `build/icon.svg`, PNG 1024 в `build/icon.png`). Нативные модули не нужны: ssh2 работает на чистом JS, `npmRebuild: false`.
- Сборка под Windows с Linux требует wine (32 и 64 бит) для NSIS.

## 18. Импорт из чужих баз

`src/main/store/foreign-parse.ts` (без electron, тест `npm run test:foreign`) читает файл: SQLite по заголовку `SQLite format 3` через sql.js (WebAssembly, без нативных модулей, поэтому сборка из Linux через wine не ломается), иначе JSON (каждый массив объектов становится таблицей, вложенные объекты разворачиваются в `credentials.username`), иначе CSV (разделитель `; , tab |` по первой строке, UTF-8 или Windows-1251). Колонки угадываются по заголовкам (рус./англ. синонимы) и по значениям: колонка адреса та, где лежат IP или имена. `buildImport` чистая функция: её результат показывается как превью (`foreign:plan`) и применяется (`foreign:apply`) через `applyImport`, так что пароли сразу шифруются safeStorage. Повтор = тот же адрес и порт. Номера папок ищутся в другой таблице с колонками id + name (+ parentId). Файл только читается; в renderer пароли не попадают, в превью замаскированы.


## 19. Сетевые инструменты

Экран «Инструменты» (`renderer/src/screens/ToolsScreen.tsx`) и пункт «Сетевые инструменты» в меню хоста и узла карты, который подставляет адрес хоста. Вкладки: Ping (непрерывный, мин/сред/макс, потери, джиттер, график), Трассировка, DNS, Порты, Скан сети (ping-обход подсети до /20 с отметкой «есть в базе / нет в базе»). Всё запускается с этого ПК, внешних сервисов нет.

- Main: `main/tools/tools.ts`. Ping и скан вызывают системный `ping` по одному запросу (`-n 1 -w`), трассировка — `tracert` / `traceroute`; вывод Windows идёт в OEM-кодировке, декодируется как CP866 (`main/tools/parse.ts`). DNS — `dns.Resolver` Node (A, AAAA, PTR, CNAME, MX, NS, TXT, SOA, SRV, свой DNS-сервер) и «как Windows» через `dns.lookup` (hosts + системный резолвер). Порты — TCP connect: «открыт», «закрыт» (RST), «нет ответа» (таймаут); можно проверять с jump-host через `forwardOut`.
- IPC: `tools:start(runId, kind, params)` → поток `tools:event`, `tools:stop(runId)`, `tools:dns`. Запуски привязаны к окну и останавливаются при его закрытии. Адрес проверяется (только имя/адрес, без опций), shell не используется.
- Экран монтируется при первом открытии и остаётся смонтированным, поэтому ping продолжает идти на других экранах.
- Тест разбора: `npm run test:tools`.

## 20. Обновления из GitHub Releases

Источник один: релизы публичного репозитория `Trapalenok/Pult`, которые собирает workflow Release. Токенов в приложении нет, анонимного лимита GitHub API (60 запросов в час на IP) хватает на проверку при запуске и по кнопке.

- Main: `main/update/updater.ts`. Проверка — `GET api.github.com/repos/Trapalenok/Pult/releases` через `net.fetch` (системный прокси Windows работает), черновики и pre-release отбрасываются. Для установленной версии берётся `Pult-Setup-X.Y.Z.exe`, для portable (`PORTABLE_EXECUTABLE_FILE`) — `Pult-X.Y.Z-portable.exe`. Ссылка обязана начинаться с `https://github.com/Trapalenok/Pult/releases/download/`.
- Скачивание в `%TEMP%\pult-update`, с прогрессом и отменой. Проверяются размер и SHA-256 из поля `digest`, которое GitHub отдаёт для файлов релиза; при несовпадении файл удаляется.
- Установка: setup запускается как `Pult-Setup.exe /S --updated --force-run` (тихая установка поверх, в ту же папку, затем Pult стартует снова), после чего Pult закрывается. Если Pult стоит в Program Files (для всех пользователей), установщик открывается обычным окном, чтобы Windows спросила права администратора. Portable: новый exe копируется рядом с текущим и запускается. Можно выбрать любую версию, в том числе старее текущей.
- Electron-updater не используется: он умеет только «до последней», не поддерживает portable и требует `latest.yml` в релизе.
- Проверка при запуске через 5 секунд, выключается в Настройках (`settings.updateCheck`); без сети она молчит. Баннер «Доступна версия» закрывается до следующей версии (localStorage `update.dismissed`).
- IPC: `update:state`, `update:check`, `update:download(version)`, `update:cancel`, `update:install`; состояние рассылается во все окна событием `update:state`. Renderer: `renderer/src/update/UpdatePanel.tsx`.
- Тест: `npm run test:update` (поддельный GitHub: выбор файла, порядок версий, контрольная сумма, portable, офлайн; `LIVE=1` дополнительно спрашивает настоящий).
